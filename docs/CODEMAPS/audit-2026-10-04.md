## Findings by consequence

### P0: Public registration can assign Admin

[RegisterRequestDTO](../../backend/user-service/src/main/java/com/w16a/danish/user/domain/dto/RegisterRequestDTO.java)
accepts a role string (line 38), and
[UsersServiceImpl.register](../../backend/user-service/src/main/java/com/w16a/danish/user/service/impl/UsersServiceImpl.java)
(85–135) looks up and assigns that role without an allowed-public-role check.
[SQL](../../mysql-init/create_table.sql) seeds `Admin` alongside other roles.
The gateway makes `/users/register` public.

**Isolated runtime reproduction:** invoking the real register method with
`role=Admin` and a valid DTO saves the Admin role ID and passes `role=Admin` into
JWT generation. DB queries, password utility, and Redis/token storage were
mocked; no production account or token was created. A browser limiting visible
role choices cannot enforce this API rule. Restrict public signup roles and keep
Admin provisioning on an authorized path.

### P1: Participant identity does not protect score/status writes

[SubmissionRecordsController](../../backend/registration-service/src/main/java/com/w16a/danish/registration/controller/SubmissionRecordsController.java)
445–450 exposes `PUT /submissions/internal/{id}/total-score`; it accepts no
RequestContext and dispatches directly to the write service.
[CompetitionsController](../../backend/competition-service/src/main/java/com/w16a/danish/competition/controller/CompetitionsController.java)
416–422 similarly exposes `PUT /competitions/{id}/status` without actor checks.
The services validate record/enum details, not actor permissions. Gateway prefix
routes forward both; hiding an OpenAPI operation does not block the route.

**Isolated runtime reproduction:** real MockMvc controllers return HTTP 200 and
invoke the respective write collaborators with Participant identity headers,
`score=999.00`, and `status=AWARDED`. Services were mocked, so this proves dispatch
and missing controller protection, not a live database mutation. Gateway routing
and the services' missing actor checks were traced statically. Separate internal
service authentication from user routes; enforce actor/object checks and allowed
Competition transitions at the appropriate domain boundary.

### P1: Submission privacy and file ownership are not enforced

[FileStorageServiceImpl](../../backend/file-service/src/main/java/com/w16a/danish/fileService/service/impl/FileStorageServiceImpl.java)
111–139 applies anonymous `s3:GetObject` to every bucket it creates, including
submissions, and upload returns a direct object URL. Existing bucket policies
are not reconciled.
[FileUploadController](../../backend/file-service/src/main/java/com/w16a/danish/fileService/controller/FileUploadController.java)
44–48 accepts bucket/object names for generic deletion without ownership checks.
[SubmissionRecordsServiceImpl.getTeamSubmissionPublic](../../backend/registration-service/src/main/java/com/w16a/danish/registration/service/impl/SubmissionRecordsServiceImpl.java)
563–590 returns a Team Submission without checking APPROVED.

**Static evidence:** callers with a known object URL may read an unapproved file;
an authenticated caller with a known key may delete another object's data;
the public Team-detail path can return non-approved submission information.
Actual deployed MinIO policies were not inspected. Enforce submission visibility
and object ownership independently of unpredictable UUID names.

### P1: Score and Winner selection bypass documented invariants

[SubmissionJudgesServiceImpl.judgeSubmission](../../backend/judge-service/src/main/java/com/w16a/danish/judge/service/impl/SubmissionJudgesServiceImpl.java)
63–129 checks assignment for the DTO competition but does not verify the supplied
submission belongs to it or is APPROVED. It accepts submitted criterion/weight
values rather than binding them to the competition criteria.
[SubmissionWinnersServiceImpl.autoAward](../../backend/judge-service/src/main/java/com/w16a/danish/judge/service/impl/SubmissionWinnersServiceImpl.java)
158–273 does not require COMPLETED or the scored-list path's minimum three judges.
Its per-criterion map keeps the first encountered score for duplicates, rather
than averaging judges' criterion scores.

**Static evidence:** a crafted score request can violate assignment/Review
boundaries; premature or unevenly judged awarding is possible; criterion awards
can depend on score iteration order. Existing passing tests do not establish
these invariants. Bind Submission, Competition, Review, criteria, and scoring
policy at the write boundary and use one explicit eligibility rule for awarding.

### P1: Submission replacement skips score/Review null resets

[SubmissionRecordsServiceImpl](../../backend/registration-service/src/main/java/com/w16a/danish/registration/service/impl/SubmissionRecordsServiceImpl.java)
sets `reviewComments`, `reviewedBy`, `reviewedAt`, and `totalScore` to null when
replacing a Submission, then calls `updateById`.
[SubmissionRecords](../../backend/registration-service/src/main/java/com/w16a/danish/registration/domain/po/SubmissionRecords.java)
does not opt those fields into unconditional updates.

**Isolated SQL-generation reproduction:** `TableInfoHelper` with the project
MyBatis configuration reports NOT_NULL for all four fields and generates a null
condition around each column assignment. These null reset values are therefore
omitted from that update SQL. The probe did not execute JDBC or read a live row.
Old scores/Review metadata can survive a replacement even when the Java object
looks cleared; assertions only on that object cannot detect this. Verify the
reset through the persisted row and make clearing explicit.

### P1: Query cache survives account changes

[QueryProvider](../../frontend/src/providers/QueryProvider.jsx) owns a module-level
QueryClient. Private keys in [queryKeys](../../frontend/src/api/queryKeys.js) do
not consistently identify the account. Logout and login change session state but
do not clear that shared cache.

**Static evidence:** a second account can initially observe a previous account's
private cached UI data in the same SPA session, even if a subsequent backend
refetch is correctly authorized. Scope private queries to identity and clear or
replace account cache state on session transitions. See the frontend map for
the affected keys and call sites.

### P2: Judge accounts lack the normal judging entry path

Judging pages exist under `Participant`, but `App.jsx` permits Participant on the
rating queue and the login/sidebar role paths lack a Judge entry. A real Judge
account therefore cannot follow the normal UI path to its assignment queue.
**Static evidence:** the browser role gate contradicts the domain's four-role
model; current rating E2E uses Participant identities and cannot detect this.

### P2: Homepage IDs and OAuth origins do not match real APIs

Homepage `TopValues` builds sample cards with array indices, and `ContestCard`
passes those IDs to real registration/voting calls; the vote path also uses a
Competition ID where a Submission ID is required. OAuth buttons in the
registration modal resolve `/users/oauth/...` against the frontend origin, while
Vite only proxies `/api` and the container serves a static SPA.
**Static evidence:** these visible UI paths do not follow the already implemented
domain service contracts. Use real entities and the shared API origin. Precise
locations and UI-test omissions are listed in [frontend findings](frontend.md).

### P2: Browser accessibility checks race with animation readiness

The browser run also found an independent **animation/readiness race**. Default
parallel execution had browser-launch/page-load timeouts. A single-worker public
accessibility rerun passed nine of ten checks, but sampled twelve low-contrast
homepage nodes during HeroPreview fade-in (ratios 1.36–1.76). A separate probe
waiting explicitly for preview opacity=1 returned zero axe violations and dark
text. This is not evidence of a permanently invalid color token, and the extra
probe does not turn the recorded suite failure into a pass. Browser acceptance
needs deterministic readiness for the state it intends to inspect.

### P2: Remote side effects lack durable recovery

Submission upload crosses MinIO, local MySQL, and synchronous RabbitMQ publication.
Notifier methods do not catch publish failures, contradicting the domain doc's
fire-and-forget claim. Upload objects cannot roll back with MySQL. Score and Award
callbacks defer remote effects until commit but provide no persistent retry if
status/score propagation or event delivery fails afterward.
**Static inference:** failures can leave orphaned objects, stale remote totals or
status, and missing notifications. See [data consistency](data.md) for trigger
points and transaction boundaries; no outage was injected into a live stack.

### P2: Deployment instructions exceed what pipelines enforce

The backend Docker build context includes the root `.env` because `.dockerignore`
does not exclude it. MySQL Compose configuration does not provision a custom
MYSQL_USER. Redis is published to the host without a password. Frontend image
dependency installs/runtime versions are not fully reproducible. Jenkins uses a
Java 21 image for a Java 23 project, does not provision the complete frontend
toolchain, omits configurable infrastructure credentials, and uses `compose ps`
as its post-deploy check instead of an exit-status health/business probe.
**Static evidence:** these are packaging/deployment limitations, not proof that
secrets have been published or that a specific running deployment failed.
See [deployment findings](dependencies.md) for exact files and operational impact.
